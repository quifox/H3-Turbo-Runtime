# 可选策略：用法、代价与验证

这些是选项，不是顺序。每条都来自实际调试，但不保证适合你的设备、时长或权重。

## 1. 确认优化路径

- **是什么**：确认当前 kernel 是优化实现，而不是通用回退或参考实现。
- **我们当时**：单步的大头落在通用整数矩阵乘上，换对路径后的收益比任何参数调优都大。
- **代价**：要读 kernel 时间线；可能要修版本门槛、布局或格式。
- **怎么验**：kernel 名、命中计数、单算子对照；不要只看总耗时。
- **也可以不选**：时间线里已经全是目标 kernel 时，这条没有可做的。

## 2. 布局与格式

- **是什么**：让权重/激活以 kernel 期望的布局存在，避免不必要的拷贝与转换。
- **我们当时**：保留原始转置视图时选到了更快的矩阵乘；复制成连续布局反而慢。
- **代价**：视图可能免费，拷贝有代价；改布局可能影响下游。
- **怎么验**：逐元素/逐位一致，加单算子耗时。
- **也可以不选**：布局已经是 kernel 期望的，或转换成本低于收益。

## 3. 消重复

- **是什么**：去掉重复计算、重复搬运、重复解包/量化。
- **我们当时**：FFN 的主权重和 LoRA 各算了一遍 SwiGLU；投影结果有多余的 LoRA 读写。
- **代价**：要读源码和时间线找重复；改动可能牵涉多个模块。
- **怎么验**：调用次数、时间线、逐位一致。
- **也可以不选**：重复本身很小，或去掉会破坏数值路径。

## 4. 融合写回

- **是什么**：把相邻算子或写回合并，减少 kernel 往返和中间物化。
- **我们当时**：QKV 和输出投影的缩放写回、LoRA 累加与门控激活，都做过融合。
- **代价**：融合会改变运算顺序，逐位验证更严格；可读性下降。
- **怎么验**：同输入逐位；有微小数值差异的放实验分支。
- **也可以不选**：中间量本来就不大，或融合收益被同步吃掉。

## 5. 分块与配对

- **是什么**：按行块、头组或瓦片处理，压峰值、减少中间张量。
- **我们当时**：FFN 按行块配对，直接把 FC1 输出喂给 FC2；行块再增大就改了数值。
- **代价**：形状要与 GEMM 对齐；分块太小会增加启动开销。
- **怎么验**：逐位或容差，加峰值和端到端。
- **也可以不选**：分块后启动开销超过收益，或数值不允许。

## 6. 权重驻留/预取/分级

- **是什么**：决定权重常驻显存、放主机、还是分级搬运；预取下一层。
- **我们当时**：分级驻留对"搬得慢"的设备有效；强制逐层预取反而多读、更慢。
- **代价**：占主机内存或显存；预取可能读多、打乱 cache。
- **怎么验**：读盘量、未重叠搬运、端到端墙钟。
- **也可以不选**：设备是"算得慢"而不是"搬得慢"。

## 7. 阶段划分与释放

- **是什么**：条件、去噪、视频、音频分进程或分阶段，逐段释放。
- **我们当时**：进主干前释放大缓冲，峰值明显下降，时间在噪声内。
- **代价**：进程启动、权重重复加载，可能增加读盘。
- **怎么验**：各阶段峰值、端到端墙钟。
- **也可以不选**：显存不紧，或进程开销超过收益。

## 8. 长序列分头/分块/流式

- **是什么**：保留完整时序，按头或瓦片分组；复用低秩投影与量化。
- **我们当时**：长序列整块 QKV 分配 OOM；分头后工作区下降，但组太小会把峰值推到输出投影。
- **代价**：启动次数增加；分组后要复用 `down(X)`、每层只量化一次。
- **怎么验**：工作区公式、整卡峰值、逐位或容差。
- **也可以不选**：序列不够长，或分组收益被启动开销吃掉。
- **注意**：按时间切分通常会破坏全局因果与量化归约；除非模型本身支持分段注意力，否则不建议。

## 9. 精度选择性处理

- **是什么**：只对异常行/块走窄路径（如 FP32 重算），正常行保持原路径。
- **我们当时**：少数音频行超过 FP16 上限；只重算异常行，全局升 FP32 代价大。
- **代价**：要定位异常、加守卫；守卫本身有开销。
- **怎么验**：有限值检查、逐位或容差、画质关键帧。
- **也可以不选**：异常是系统性的，窄路径救不了。

## 10. 解码分块/裁剪

- **是什么**：调整 VAE tile/overlap；只加载解码需要的权重。
- **我们当时**：缩小重叠明显提速，但像素有变化；只载解码器省显存，输出逐位一致。
- **代价**：像素变化；tile 太小可能出接缝。
- **怎么验**：同一潜变量的 PSNR/MAE，加关键帧。
- **也可以不选**：画质预算不允许像素变化。

## 11. 适配器与配方

- **是什么**：确认 variant、target 覆盖、rank/alpha、步数、采样配方匹配。
- **我们当时**：能加载不等于能少步；部分 target 也会"跑"，但结果不是作者训练的那条路径。
- **代价**：要读权重元数据、target map、作者配方。
- **怎么验**：target 覆盖、潜变量哈希、画质。
- **也可以不选**：继续用已验证的默认组合。

## 12. 微调

- **是什么**：寄存器、线程、瓦片、warp 等参数。
- **我们当时**：局部有收益，但整步经常只快一点点，甚至落在噪声里。
- **代价**：换设备或换形状要重调；收益不稳定。
- **怎么验**：局部 A/B，加真实单步，加整镜。
- **也可以不选**：大项还没做完时，先不动。

## 13. 复用条件与中间结果

- **是什么**：把可复用的条件、映射、中间结果留下来，避免重复编码、重复加载、重复计算。
- **我们当时**：同一镜头的条件缓存、同进程复用模型与 LoRA 映射，省掉了重复编码和冷读。
- **代价**：占内存或显存；缓存失效要重算，脏缓存会误导对比。
- **怎么验**：重复运行的准备阶段墙钟、读盘量、结果一致。
- **也可以不选**：任务每次换条件，命中率低。

## 14. 换实现/后端

- **是什么**：换一个更匹配当前设备的 kernel、库或后端，而不是等现有实现自动回退。
- **我们当时**：同一算子在不同库/不同实现下差异明显；换到匹配的路径后才拿到收益。
- **代价**：要维护多套路径；要逐位或容差验证。
- **怎么验**：单算子 A/B，加真实单步，加整镜。
- **也可以不选**：现有实现已经匹配，或换实现会破坏数值。

## 15. 试过但没采用

- **全局升精度**：代价大、收益小；只在异常无法定位时考虑。
- **按时间切分长序列**：破坏因果，不要。
- **强制逐层预读**：可能多读、更慢。
- **把余量拿去常驻权重**：时间未必变。
- **盲目加 CPU 线程**：可能更慢，或落在噪声里。
- **过大的行块**：可能改数值。
- **更小或更大的分头组**：峰值可能转移到别处，收益不一定有。
- **只在小缓存/小显存成立的优化**：标记为设备相关，不要写成通用结论。
- **近似注意力/稀疏化**：会改变数值，需要单独的质量验证；当时没有采用。
