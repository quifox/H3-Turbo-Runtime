# H3 Turbo Runtime 优化经验

## 0. 这份 Skill 怎么用

换设备、加长时长、放大分辨率、接新 LoRA 或新采样配方时，用它来组织工作。

它给的是一个循环、一套 Profile 方法、一组可选策略。策略没有先后，用不用、先看哪个，由 Profile 的结果决定。它不是配置表，也不是规则清单。

## 1. 优化循环

1. **跑通并固定任务**：同一镜头、种子、条件、权重。没有可重复的任务，后面所有对比都不成立。

   换设备时，先确认这几件事再谈快慢：架构与 kernel 资格（走不走得通，走不通就显式换后端）、数值路径（权重格式、激活精度、归一化/写回的 dtype）、显存预算（权重、激活、工作区、输出分开算）、正确性（输出有限、形状对、与参考在容差内）。
2. **拆开**：端到端阶段 → 模块 → kernel。先知道时间花在哪一层。
3. **判断**：这块值不值得动。占比大不等于可优化；热点可能已经到上限；收益可能太小。
4. **隔离验证**：真实形状、真实权重、单变量；先看数值，再看时间。
5. **接回**：真实单步 → 整镜；看局部收益能不能兑现。
6. **决策**：端到端收益大于噪声才留；否则回滚。
7. **收敛**：边际收益小于噪声就停，冻结配置并记录。

循环会重复：瓶颈转移后，回到第 2 步。

## 2. Profile：把瓶颈拆开

### 2.1 三层拆解

**L1 端到端阶段**：条件准备、去噪、视频解码、音频解码、封装。每段记墙钟和整卡显存峰值。

**L2 模块**：去噪内部拆 FFN、注意力核心、QKV/输出投影、归一化与位置编码、LoRA、其他；解码内部拆分块、重叠、后处理。

**L3 kernel**：名字、耗时、调用次数、空窗、主机到设备的拷贝、拷贝与计算的重叠。

只有拆到 L3，才能区分"慢在算法"还是"慢在路径、布局、同步"。

### 2.2 每次要记什么

- 墙钟
- 整卡显存峰值（驱动采样）
- 框架分配峰值与保留峰值
- 读盘量
- kernel 名与耗时
- GPU 忙/闲与空窗
- 主机到设备的拷贝量，以及其中未与计算重叠的部分

冷启动和热启动分开记；同一进程复用映射后再记一次。

### 2.3 判断瓶颈类型

| 类型 | 看什么 | 通常往哪想 |
|---|---|---|
| 计算密集 | 算力达成率、占用率、Tensor Core 利用 | 融合、分块、布局、精度路径 |
| 带宽密集 | 带宽达成率、cache 命中、布局 | 布局、融合、减少中间物化 |
| 延迟/占用 | kernel 太小、启动次数多、尾部效应 | 合并 kernel、增大工作块 |
| 同步 | 流等待、主机同步、kernel 间空窗 | 异步、重叠、减少同步点 |
| IO | 读盘、缺页、冷启动 | 复用映射、预取、分级驻留 |
| 显存 | 权重、激活、工作区、输出缓冲 | 分块、阶段释放、分头 |

类型判断错，后面的策略通常白做。带宽问题当算力问题调，就是典型。

### 2.4 找浪费

- 通用路径、静默回退
- 重复计算、重复搬运、重复解包/量化
- 中间物化、布局转换
- 未与计算重叠的拷贝
- 空窗

### 2.5 控制变量

- 同一任务、输入、权重。
- 冷热分离；同进程复用。
- 一次只动一个。
- 先量噪声带，再谈收益。

### 2.6 常见陷阱

- 只看总耗时，不看拆解。
- 只看占比，不问剩余空间。
- 冷热混用，把 IO 当算子收益。
- 拿局部收益当整步收益。
- 代码里有，就当这次跑到。
- 微基准快，端到端不动。

## 3. 可选策略

下面都是选项，不是顺序。每条的具体用法、代价和验证方式见 `references/strategies.md`。

- **确认优化路径**：看 kernel 名与命中，先排除静默回退和通用实现。
- **布局与格式**：视图可能免费，拷贝有代价；布局会决定选到哪个 kernel。
- **消重复**：重复计算、重复搬运、重复解包/量化。
- **融合写回**：减少 kernel 往返和中间物化。
- **分块与配对**：压峰值、减少中间张量；形状要与 GEMM 对齐。
- **权重驻留/预取/分级**：只在搬运是瓶颈时值得。
- **阶段划分与释放**：通常换空间，不换时间。
- **长序列分头/分块/流式**：序列变长时注意力/QKV 超线性增长。
- **精度选择性处理**：异常行走窄路径，不做全局升降。
- **解码分块/裁剪**：省显存或时间，但会改像素。
- **适配器与配方**：variant、target 覆盖、步数、采样配方。
- **微调**：寄存器、线程、瓦片；局部收益常被整步吃掉。

还有一类是**试过但没采用**的方向，见 `references/strategies.md` 末尾；它们同样是经验。

## 4. 验证与收敛

### 4.1 逐位还是容差

- **逐位**：同一算法，只改融合、写回或顺序无关。同输入、同权重，输出逐位相等。
- **容差**：改精度、分块、重叠、调度、设备。报 PSNR/SSIM/MAE，并看关键帧。

两者不能混用。系统级量化或换设备不做逐位承诺；逐位也不等于画质等价。

### 4.2 关键帧

看脸、手、接缝、文字、快速动作。指标过了，不代表画质过了。

### 4.3 可复现

版本、命令、种子、条件哈希、kernel 命中计数。

### 4.4 什么时候停

- 边际收益小于噪声。
- 画质预算用尽。
- 换设备后不成立。
- 下一步要改数学不变量——那不是调优，是换模型。
