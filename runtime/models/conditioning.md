# H3 Turbo conditioning contract

The public CLI accepts `--condition` as a local Safetensors file encoding text, optional time-aligned image guides, and the initial video/audio latents. The data must match **the requested duration**. H3's native timeline uses a `17k+5` frame grid at 24 fps; the exported video contains the requested integer number of frames, and the final audio stream is trimmed or padded to the same duration.

| Key | Dtype | Shape | Purpose |
|---|---|---|---|
| `text` | FP32 | `[1, L, 5120]` | Projected text tokens |
| `token_tags` | INT64 | `[L]` | H3 text token tags |
| `video_init` | FP32 | `[1, 24, 5k+2, H/16, W/16]` | Initial video latent |
| `audio_init` | FP32 | `[1, 32, 2, round((17k+5)·40/24)]` | Initial audio latent |
| `frame_i` | FP32 | `[1, 24, 1, H/16, W/16]` | Legacy image guide at native frame `i` |

The encoder creates these tensors using H3's own ComfyUI conditioning nodes. Do not copy latents between incompatible duration/size requests. Existing `frame_i` files remain supported by the loader; new conditions use v2 metadata to represent H3's full audiovisual conditioning structure.


## First/last frames, timeline guides and reference imagery

MiniMaxH3ImageToVideo first/last images anchor the corresponding output boundary.
MiniMaxH3AddGuide attaches an image or clip to a selected native-frame position.
MiniMaxH3ReferenceToVideo consumes identity/style references which do not
have to appear as exact output frames. Ref2VA reference conditioning requires
the compatible Ref2VA backbone and LoRA, not just a FL2VA weight file.

The ComfyUI node supports these conditioning types and mixtures of guides.
Use the native frame index for guides, independently of the chosen output FPS.

## Native audiovisual conditioning (schema v2)

The release uses `safetensors` tensor storage and the string-only file metadata fields `h3_conditioning_schema=2`, `h3_guides`, and `h3_refs` (the latter two are JSON arrays). This format preserves the exact **ordered lists** expected by MiniMaxH3's `minimax_keyframes` and `minimax_refs` parameters. Example tensor keys:

| Data | Tensor key | Descriptor data |
|---|---|---|
| Timeline still / short-clip anchor | `guide_N_video` | `frame`, `video_key` |
| Timeline audio anchor | `guide_N_audio` | `frame`, `audio_key` |
| Reference image or reference clip | `ref_N_video` | `kind`, `latent_t`, `latent_h`, `latent_w`, `video_key` as applicable |
| Reference audio / video soundtrack | `ref_N_audio` | `kind`, `ref_audio_t`, `audio_key` |

The video and audio tensor values and their layouts are generated by the upstream native H3 nodes: `MiniMaxH3ImageToVideo`, `MiniMaxH3AddGuide`, and `MiniMaxH3ReferenceToVideo`. Both the fast and streaming denoiser paths load the same structure. For reference video+audio the reference metadata retains both streams and their time alignment. For timeline guides, negative frame numbers are resolved by H3 when preparing the file. Existing schema v1 files remain readable, and no reference capability is disabled merely because the example benchmarks used only first/last frames.

The following shapes are **measured examples**, not hardcoded constraints on the streaming sampler:

| Exported video | Native frames | `video_init` | `audio_init` |
|---|---:|---|---|
| 5 s, 120 frames | 124 | `[1, 24, 37, 30, 52]` | `[1, 32, 2, 207]` |
| 15 s, 360 frames | 362 | `[1, 24, 107, 30, 52]` | `[1, 32, 2, 603]` |

These examples use 832×480. The optimized Ada fast path is specifically qualified for the five-second case; the generic streamed calculation accepts a compatible longer conditioning file. The release includes no embedded weights or encoded example files. Use the ComfyUI node or a matching H3 encoder to create conditions.
